# FreeDom Launcher: полный концепт фишек

## Идея проекта

Лаунчер для Minecraft, который экономит время (пресеты, автоматизация, умный поиск), даёт свободу (любые аккаунты, глубокая кастомизация) и дружит со Steam. Пометки: **\[В\]** ваша идея, **\[Я\]** предложил я, **\[В+Я\]** ваша идея, развитая вместе.

## 1. Запуск и настройки

- **\[В\]** Аргументы Java, установка Java, выделение ОЗУ.
- **\[В+Я\]** Умная рекомендация ОЗУ: учитывает объём памяти ПК, число модов и версию, объясняет выбор и предупреждает о слишком большом значении (например, ПК с 16 ГБ, игре предлагается 8 ГБ, а для сборки из 120 модов рекомендуется 6 ГБ).
- **\[Я\]** Мастер первого запуска: определяет железо и спрашивает, что человек хочет играть («ваниль», «оптимизация», «технологии»), затем предлагает стартовые пресеты.
- **\[Я\]** Быстрый запуск последней сборки, предзагрузка библиотек и ассетов, пока пользователь настраивает сборку.

## 2. Аккаунты и скины

- **\[В\]** Лицензия через вход Microsoft: лаунчер не видит пароль от Xbox. Нужна регистрация приложения в Azure.
- **\[В\]** Ely.by (отдельная система авторизации, authlib-injector).
- **\[В\]** Игра по нику: пользователь вводит ник и заходит с ним.
- **\[В\]** Скины: у лицензии видны всем, у Ely.by только пользователям Ely.by, у игры по нику можно выбрать любой, но виден он только владельцу.
- **\[Я\]** Честная пометка в интерфейсе: ник без лицензии не зайдёт на серверы с `online-mode=true`.

## 3. Управление сборками и контентом

- **\[В\]** Установка модов, карт, ресурспаков, датапаков и шейдеров с Modrinth и CurseForge, не выходя из лаунчера.
- **\[В+Я\]** Вопрос про зависимости: «у проекта FerriteCore есть зависимости, вы хотите их добавить?» Плюс кнопка «установить все» и разделение на обязательные и опциональные.
- **\[Я\]** Для CurseForge нужен API-ключ, и часть модов запрещает скачивание вне сайта, поэтому лаунчер показывает ссылку для ручной загрузки.
- **\[Я\]** Профили: импорт и экспорт (.mrpack, сборки CurseForge, zip), дублирование, изолированные папки.
- **\[Я\]** Установка загрузчиков: Fabric, Forge, NeoForge, Quilt.
- **\[Я\]** Автообновление модов с проверкой совместимости, снимок сборки перед рискованным обновлением и откат.
- **\[Я\]** Отключение мода переключателем вместо удаления, режим поиска проблемного мода (лаунчер отключает половину модов и сужает круг), заметки к модам, предупреждения о конфликтах.
- **\[Я\]** Единое хранилище файлов: одинаковые jar и ассеты хранятся один раз.

## 4. Пресеты модов (синхронизация)

**\[В+Я\]** Главная «фишка-крючок». Пользователь выбирает моды из одной сборки (Sodium, Lithium, FerriteCore и т. д.), сохраняет их как пресет, и при создании новой сборки лаунчер спрашивает, добавлять ли их.

- Хранятся ID проектов, а не файлы. Лаунчер сам подбирает версию мода под нужную версию Minecraft и загрузчик.
- Именованные пресеты: «Оптимизация», «Мини-карта», «Мои любимые».
- При смене версии пресет проверяется заново: «Для 1.21.4 недоступны X и Y. Добавить остальные?» Можно включить слежение, чтобы лаунчер сообщил, когда эти моды появятся.
- Пресет привязан к загрузчику (для Forge свои аналоги, например Embeddium вместо Sodium).
- Уже установленные моды пропускаются, зависимости обрабатываются той же логикой, что и при обычной установке.
- Экспорт и импорт в JSON, импорт коллекций Modrinth.
- Копирование при создании сборки проще и безопаснее, чем автоматическое изменение всех связанных сборок.

## 5. Умный поиск

**\[В+Я\]** Поиск по проектам Modrinth и CurseForge исправляет неверную раскладку: запрос «ыщвшгь» ничего не находит, и лаунчер пишет «Ничего не найдено. Возможно, вы имели в виду sodium?»

- Запрос отправляется как есть и параллельно в преобразованном виде по таблице раскладки (ы→s, щ→o, в→d, ш→i, г→u, ь→m).
- Лаунчер не заменяет запрос молча, а спрашивает.
- Проверка включается, только если в запросе есть кириллица.
- Таблицы для разных раскладок: русская, украинская, казахская.
- **\[Я\]** Транслитерация: «содиум», «литиум», «ферритекор» превращаются в sodium, lithium, FerriteCore.
- **\[Я\]** Опечатки («sodum»), собственные псевдонимы («оптимизация», «fps» показывают Sodium, Lithium, FerriteCore), локальный кэш популярных проектов для мгновенных подсказок.
- Те же подсказки в поиске серверов, сборок, настроек и по Ctrl+K.

## 6. Встроенные моды для чата

**\[В+Я\]** Лаунчер предлагает добавить в сборку свои моды, которые исправляют ввод в чате.

### Мод 1: исправление раскладки в чате

Пример: `.пшму ТШК_УД вшфьщтв 64` превращается в `/give NIR_EL diamond 64`, потому что `.` на русской раскладке стоит на клавише `/`.

- Мод перехватывает сообщение до отправки, определяет неверную раскладку по первому символу, преобразует текст и проверяет, что первое слово есть среди команд сервера.
- Показывает вопрос: «Похоже, вы забыли переключить раскладку. Отправить `/give NIR_EL diamond 64`?» с вариантами «Да» и «Нет».
- Обычный русский чат не трогается, ничего не уходит на сервер без подтверждения (автоисправление можно сделать настройкой).

### Мод 2: T9 и автоисправление в чате

- Подсказки слов над строкой чата, Tab принимает первую, исправление опечаток по словарю (например, алгоритм SymSpell), личный словарь.
- По умолчанию режим «только подсказки», автозамена включается в настройках, в командах T9 не работает.
- Backspace сразу после замены возвращает исходное слово, в словарь добавляются игровые слова («крипер», «незер», «спавн»).

### Технические моменты

- Моды пишутся на Java или Kotlin, а не на C#. Для Fabric есть события для перехвата чата (`ClientSendMessageEvents`).
- Нужны отдельные сборки под версии и загрузчики, поэтому лучше сразу взять мультиверсионный шаблон (Stonecutter или Architectury).
- Моды только клиентские, игровых преимуществ не дают.
- Публикация на Modrinth позволит обновлять их через лаунчер и давать ими пользоваться людям без лаунчера.
- В лаунчере: раздел «Встроенные моды», пресет «Удобство», выбор языка раскладки в настройках.

## 9. Steam

- **\[В\]** Добавление лаунчера как сторонней игры: общение с друзьями через оверлей Steam, приглашения на сервер (IP, версия, наличие белого списка).
- **\[Я\]** В первой версии приглашение работает как «скопировать текст», полная интеграция потребует Steamworks API или обходного пути.

### Ярлыки сборок и запуск из Steam

**\[В+Я\]** Для каждой сборки можно сгенерировать .bat (на Linux и Steam Deck .sh), который запускает именно её, и добавить его в Steam как отдельную «игру».

- Запуск через аргументы: `FreeDomLauncher.exe --launch <id-сборки>` и `--server play.example.com`.
- Лаунчер остаётся запущенным, пока идёт игра, иначе Steam решит, что вы закончили играть. В bat используется `start /wait`.
- В bat указывается уникальный ID, а не имя сборки, пути берутся в кавычки (проверить кириллицу и пробелы).
- Если токен Microsoft истёк, показывается окно входа, а не тихая ошибка.
- Оверлей Steam с Java работает не всегда, это нужно честно указать в описании.
- Позже: кнопка «Добавить в Steam» (правка `shortcuts.vdf`, Steam должен быть закрыт), иконка и обложка из скриншота сборки.

## 13. Технологии

- C# с Avalonia UI (WPF, если нужен только Windows), библиотека CmlLib.Core для запуска игры, Steamworks.NET для интеграции со Steam. Моды для чата пишутся на Java или Kotlin.
- Альтернатива для быстрого прототипа: Python с `minecraft-launcher-lib` и PySide6, но для гибкой кастомизации лучше C#.
- Нужно решить, будет ли код открытым.

## 14. Порядок разработки

1. **База:** запуск игры, вход по нику, аккаунты Microsoft и Ely.by, профили, загрузчики.
2. **Моды:** Modrinth и CurseForge, зависимости, пресеты, умный поиск, отключение модов переключателем.
3. **Удобство:** разбор крашей, бэкапы миров, пинг серверов, галерея.
4. **Steam:** аргументы `--launch`, генерация bat и sh, затем оверлей и приглашения.
5. **Моды для чата:** сначала исправление раскладки, потом T9.
6. **Кастомизация:** темы и градиенты, шрифты, ресурспаки интерфейса, раскладки.

**Главные «крючки» для описания проекта:** пресеты модов, умный поиск с исправлением раскладки, сборки как отдельные игры в Steam, разбор крашей, глубокая кастомизация.
